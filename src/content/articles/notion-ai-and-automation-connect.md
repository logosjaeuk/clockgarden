## 1. 노션 내장 자동화(Automations)의 등장과 패러다임 변화

과거 노션에서 "상태가 '완료'로 바뀌면 완료일을 오늘 날짜로 기록하고 팀 슬랙에 알림을 보낸다" 같은 자동화를 구현하려면 Zapier나 Make(구 Integromat) 같은 외부 유료 SaaS를 구독해야 했습니다. 설정도 복잡하고 API 요청 횟수 제한 때문에 비용 부담도 상당했습니다.

그러나 노션의 **데이터베이스 자동화(Database Automations)** 기능이 공식 업데이트되면서, 노션 내부에서 트리거(Trigger)와 액션(Action)을 몇 번의 클릭만으로 설정할 수 있게 되었습니다.

업무 누락을 방지하고 팀 협업 생산성을 200% 끌어올리는 필수 자동화 시나리오 4가지를 소개합니다.

---

## 2. 자동화의 기본 작동 공식: 트리거(Trigger)와 작업(Action)

노션 자동화의 설정 원리는 직관적입니다:

```
[만약 이 이벤트가 발생하면 (When / Trigger)]
  ➔ [이 작업을 자동으로 실행하라 (Then / Action)]
```

### 지원되는 주요 트리거
- 페이지가 추가되었을 때
- 특정 속성(상태, 담당자, 마감일 등)이 특정 값으로 변경되었을 때
- 체크박스가 선택되었을 때

### 지원되는 주요 액션
- 다른 속성값 자동 변경 (예: 완료일 = 지금)
- 새 페이지 자동 생성 (예: 표준 체크리스트 자동 추가)
- 슬랙(Slack) 채널로 즉시 메시지 발송
- 웹훅(Webhook) URL로 JSON 페이로드 전송

## 3. 실무 시나리오 1: 상태가 '완료'로 바뀔 때 '완료 일시' 자동 기록

많은 프로젝트 관리자가 "이 일 언제 끝났어요?"라고 팀원들에게 일일이 물어봅니다. 팀원이 태스크 상태를 바꾼 정확한 시점을 시스템이 자동으로 기록하게 만듭니다.

### 설정 방법:
1. `태스크 DB` 우측 상단의 **번개 아이콘(⚡ 자동화)** 클릭 ➔ **[+ 새 자동화]**
2. **트리거 설정:**
   - 속성 선택: `상태`
   - 조건: `완료`로 변경됨
3. **작업(Action) 설정:**
   - 작업 선택: **[속성 편집]**
   - 속성: `완료일`
   - 값: **[지금(Now)]** 또는 **[오늘(Today)]**

이제 팀원이 칸반 보드에서 카드를 '완료' 칼럼으로 끌어다 놓는 순간, `완료일` 열에 현재 타임스탬프가 0.1초 만에 자동 기록됩니다.

## 4. 실무 시나리오 2: 긴급 버그 접수 시 Slack 채널 즉시 멘션 발송

고객지원팀이나 QA팀이 버그 DB에 긴급 이슈를 등록했을 때, 개발팀이 노션을 켜보지 않고도 슬랙에서 즉시 감지할 수 있도록 연동합니다.

### 설정 방법:
1. `버그 트래커 DB` ➔ 자동화 생성
2. **트리거:**
   - 조건: `우선순위` 속성이 `🚨 긴급(Critical)`으로 설정됨
3. **작업:**
   - 작업 선택: **[Slack 알림 보내기]**
   - 채널 선택: `#dev-emergency-alerts`
   - 메시지 내용 구성:
     ```
     🚨 [긴급 버그 등록]
     - 제목: @이름(페이지 링크)
     - 보고자: @생성자
     - 현상 요약: @요약
     지금 즉시 확인해 주세요!
     ```

이 설정 하나만으로 치명적인 장애나 고객 불만 이슈의 내부 대응 시간이 평균 45분에서 5분 이내로 단축됩니다.

## 5. 실무 시나리오 3: 웹훅(Webhook)을 통한 외부 시스템 연동

노션 플러스 플랜 이상에서는 **웹훅 전송 액션**을 지원합니다.

예를 들어 신규 고객 계약 페이지가 생성되면 사내 백엔드 API나 회계 시스템 웹훅 엔드포인트(`https://api.mycompany.com/notion-contract`)로 계약금액과 사업자번호가 담긴 JSON 데이터를 자동 전송할 수 있습니다.

```json
{
  "event": "page_created",
  "database_id": "8a3b...",
  "page_id": "c19f...",
  "properties": {
    "계약명": "2026 연간 유지보수 계약",
    "공급가액": 15000000,
    "고객사": "주식회사 테크놀로지"
  }
}
```

별도의 서드파티 브릿지 서버 없이도 노션이 사내 엔터프라이즈 ERP의 입력 프론트엔드 역할을 완벽하게 수행하게 됩니다.

## 6. 자동화 설정 시 반드시 주의할 점

1. **무한 루프 방지:** A 자동화가 B 속성을 바꾸고, B 자동화가 다시 A 속성을 바꾸는 순환 참조(Loop)가 발생하지 않도록 트리거 조건을 명확히 한정하세요.
2. **권한 확인:** 슬랙 알림을 보낼 채널에 노션 공식 봇(`@Notion`)이 미리 초대(`invite`)되어 있어야 알림 전송 실패가 발생하지 않습니다.
3. **단순함 유지:** 한 데이터베이스에 10개 이상의 과도한 자동화를 걸어두면 사용자가 카드 하나를 움직일 때마다 지연(Latency)이 발생할 수 있으므로, 팀원들에게 진짜 필요한 핵심 규칙 3~4개에 집중하세요.
