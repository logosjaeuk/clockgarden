## 1. 노션이 엉망진창이 되는 가장 흔한 원인: '평면 데이터의 늪'

많은 개인과 스타트업이 노션을 도입할 때 범하는 가장 치명적인 실수는 **하나의 거대한 표(Flat Table)** 안에 프로젝트, 세부 일정, 회의록, 담당자, 리소스 링크까지 모두 때려 박는 것입니다.

처음 한두 달은 편리해 보이지만, 데이터가 100건만 넘어가도 다음과 같은 대혼란이 발생합니다:
- 똑같은 프로젝트명을 수십 번 오타를 내며 수동 입력해야 함.
- 회의록에서 나온 할 일이 어디에 적혀 있는지 찾을 수 없음.
- 프로젝트 전체의 실시간 진행률이나 소요 예산을 자동으로 합산할 수 없음.

이 문제의 유일한 해법은 관계형 데이터베이스(Relational Database)의 원리를 노션 워크스페이스에 올바르게 적용하는 것입니다.

---

## 2. 실무 3대 코어 데이터베이스 삼각편대

성공적인 노션 워크스페이스를 운영하려면 최소한 다음 3개의 핵심 데이터베이스가 서로 분리되어 존재해야 합니다:

```
[ 1. 프로젝트 DB (Projects) ]
       │  (1 : N 관계)
       ▼
[ 2. 태스크 DB (Tasks) ]
       ▲  (N : M 관계)
       │
[ 3. 회의록 DB (Meetings) ]
```

### ① 프로젝트 DB (상위 목표)
- 특징: 시작일과 마감일이 명확하며, 최종 산출물이 존재하는 거시적 과업.
- 속성: 프로젝트명, 상태(준비/진행/완료), 기간, 담당 PM, 목표(KPI).

### ② 태스크 DB (실행 단위)
- 특징: 1~3일 이내에 단일 담당자가 완료할 수 있는 구체적 행동 단위.
- 속성: 할 일 이름, 담당자, 마감일, 우선순위, 체크박스.
- **관계형 속성:** `프로젝트 DB`와 1:N 연결 (하나의 프로젝트 아래 여러 태스크가 종속).

### ③ 회의록 DB (협업 및 의사결정)
- 특징: 언제, 누가 모여, 어떤 논의를 거쳐 어떤 결정을 내렸는지의 기록.
- 속성: 회의 제목, 일시, 참석자, 안건.
- **관계형 속성:** `프로젝트 DB` 및 `태스크 DB`와 연결 (회의 중 결정된 액션 아이템이 즉시 태스크 DB에 생성).

## 3. 1:N 관계 설정과 양방향 링크의 실전 구축

### 1단계: 관계형 속성 추가
1. `태스크 DB`에서 새 열 추가 ➔ 유형을 **[관계형(Relation)]**으로 선택.
2. 대상 데이터베이스로 `프로젝트 DB`를 지정.
3. **[양방향 관계 표시(Show on Projects)]** 토글을 반드시 활성화합니다.

### 2단계: 프로젝트 진행률 자동 롤업(Rollup)
프로젝트 DB에서 연결된 태스크들의 완료 여부를 자동으로 퍼센트 바로 집계하도록 설정합니다:
1. `프로젝트 DB`에서 새 열 추가 ➔ **[롤업(Rollup)]** 선택.
2. 관계형: `태스크`
3. 속성: `체크박스(또는 상태)`
4. 계산: **[선택된 항목 비율(Percent Checked)]** 또는 **[완료 비율]** 선택.
5. 표시 방식: **[막대(Bar)]** 또는 **[원(Ring)]** 선택.

이제 팀원들이 태스크 시트에서 체크박스를 누를 때마다, 프로젝트 대시보드의 진행률 바가 0%에서 100%로 실시간 차오르는 완벽한 자동화 파이프라인이 완성됩니다.

## 4. 데이터베이스 뷰(Linked Database View)를 활용한 템플릿 자동화

프로젝트 DB에서 **새 페이지 템플릿**을 생성할 때, 페이지 본문에 태스크 DB의 '링크된 데이터베이스 보기'를 넣고 **셀프 필터(Self-referencing Filter)**를 걸어두면 마법 같은 일이 일어납니다.

1. `프로젝트 DB` ➔ 우측 상단 드롭다운 ➔ **[새 템플릿]** 클릭 (예: `기본 프로젝트 템플릿`).
2. 페이지 본문에 `/링크된 데이터베이스 보기` 입력 후 `태스크 DB` 선택.
3. 필터 설정: `프로젝트` 속성이 **[기본 프로젝트 템플릿(현재 템플릿 이름)]**과 일치하는 항목만 보기.

### 결과:
앞으로 새로운 프로젝트 페이지를 열고 이 템플릿을 적용하면, 그 페이지 안에서 만드는 모든 하위 할 일들이 **해당 프로젝트와 자동으로 관계형 연결**되어 저장됩니다. 일일이 프로젝트를 수동으로 매핑할 필요가 전혀 없습니다.

## 5. 데이터베이스 비대화 방지 및 속도 유지 꿀팁

- **지나친 양방향 관계형 남발 금지:** 실제로 조회가 필요 없는 관계는 단방향으로 유지하여 인덱스 부하를 줄이세요.
- **아카이브 뷰 활용:** 완료된 프로젝트와 태스크는 기본 뷰에서 숨기고(Filter: 상태 != 완료), 별도의 '보관소(Archive)' 탭으로 분리하세요.
- **수식 속성 최소화:** 너무 많은 복잡한 수식이 걸려 있는 뷰는 렌더링 지연의 원인이 됩니다.

체계적인 관계형 모델링을 한 번 세팅해 두면, 팀이 성장하고 업무가 수천 건 쌓여도 노션 워크스페이스가 흔들림 없이 단단하게 유지됩니다.
